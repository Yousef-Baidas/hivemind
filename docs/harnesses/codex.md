## 2. Hook wire format quick reference (Codex)

Input (stdin, one JSON object): `session_id, transcript_path|null, cwd, hook_event_name, model, permission_mode, turn_id` + per event: `source` (SessionStart), `prompt` (UserPromptSubmit), `tool_name, tool_input, tool_use_id` (+`tool_response` for Post), `trigger` (compact), `stop_hook_active, last_assistant_message` (Stop/SubagentStop), `agent_id, agent_type, agent_transcript_path` (subagent events; `agent_id`/`agent_type` also present on tool/prompt/compact hooks fired in subagents per schema).
Output (stdout JSON): `continue, stopReason, systemMessage, suppressOutput, decision("block"), reason, hookSpecificOutput{hookEventName, additionalContext, permissionDecision, permissionDecisionReason, updatedInput, decision{behavior,message}}`.
Exit 0 + empty = continue. Exit 2 + stderr = block/continue-with-reason (PreToolUse, PostToolUse, UserPromptSubmit, Stop, SubagentStop). Context returned is capped ~2,500 tokens (spills to `<tmp>/hook_outputs/<session>/<uuid>.txt`; raise via `additionalContextLimit`).
Multiple matching hooks run CONCURRENTLY (so ordering-dependent chains are not possible). Project hooks load only in trusted projects.

## 3. Notes and gotchas for a Proteus port

- Claude-Code-hook parity is the best news: event names (`PreToolUse`, `PostToolUse`, `SessionStart`, `UserPromptSubmit`, `Stop`, `SubagentStop`, `PreCompact`), matcher-regex semantics, exit-2 blocking, `additionalContext`, `stop_hook_active` anti-loop all match. Differences: config lives in `.codex/hooks.json` / config.toml, tool names are `Bash`, `apply_patch` (matched also as `Edit`/`Write`; input is a patch in `tool_input.command`, not `file_path`), `Agent` alias for `spawn_agent`; hook trust review step; `PreToolUse` cannot `ask`.
- Model-ladder enforcement: lead's model cap could be enforced by a PreToolUse hook on matcher `Agent`/`spawn_agent` inspecting `tool_input.model`/`reasoning_effort` (deny with reason). Inference; not verified end to end.
- Codex does not auto-spawn subagents; instructions in AGENTS.md or a skill must say "spawn agents". The lead skill text must therefore be explicit.
- Subagent hook `session_id` = parent's; distinguish worker hooks via `agent_id`/`agent_type` fields (schema-confirmed on tool hooks; docs table lists them only for Subagent* events).
- Dev cadence is very fast (releases daily, alpha channel 0.160.0-alpha.x as of 2026-09-29); hooks page says main-branch schema may include fields not in the current release; treat the generated schemas as forward-looking.
- Skills dir is `.agents/skills`; Cursor and Amp read the same convention (Amp also `.claude/skills`), so a skill authored to `.agents/skills` is portable across all three.
- AGENTS.md is the cross-harness instruction file (Codex, Amp, Cursor CLI all read it; Cursor also CLAUDE.md).
