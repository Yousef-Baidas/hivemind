## Extension events (types.ts main; hooks payloads)
- Session: `session_start` {reason: startup|reload|new|resume|fork, previousSessionFile?}; `session_shutdown` {reason, targetSessionFile?}; `session_before_switch/fork/tree`, `session_tree`, `session_info_changed`; `project_trust` {cwd} -> {trusted: yes|no|undecided, remember?}; `resources_discover`.
- Inject context at session start: NO direct return on session_start; do it at `before_agent_start` {prompt, images, systemPrompt (readonly), systemPromptOptions (mutable sections)} -> result {message?: {customType, content, display, details}, systemPrompt?}; or `context` event (transform messages), `pi.sendMessage`, `pi.appendEntry`.
- User prompt submit: `input` {text, images, source, streamingBehavior} -> {action: continue | transform{text} | handled}. Extension commands take precedence over templates; `input` sees raw text first.
- Before tool: `tool_call` {toolCallId, parentToolCallId?, toolName, input} -> {block?: true, reason?: string, terminate?: bool}; `event.input` mutable in place. Handler that throws blocks (fail-safe). Handlers run in load order; tools of one assistant message can run in parallel. Typed variants for bash, read, edit, write, grep, find, ls, powershell + custom.
- After tool: `tool_result` {toolCallId, toolName, input, content, structuredContent?, isError, usage?} -> {content?, details?, structuredContent?, isError?, usage?}; handlers chain. Also `tool_execution_start/update/end`.
- Agent end / force continue: `agent_end` {messages} (notification; also JSON event has `willRetry`); `agent_before_settle` and `turn_end` handlers return {entries?: [custom|custom_message|context_edit|compaction drafts], continue?: true} = one more model request (guard against loops). `agent_settled` = final, notify-only.
- Compaction: `session_before_compact` {preparation, branchEntries, customInstructions, reason: manual|threshold|overflow, willRetry, signal} -> {cancel?/compaction?} (see types.ts SessionBeforeCompactResult); `session_compact` {compactionEntry, fromExtension, reason}; `session_compact_failed`.
- Other: `model_select`, `thinking_level_select`, `user_bash`, `message_start/update/end` (message_end can replace message), `turn_start`, `before_provider_request`, `after_provider_response`, `provider_stream_event`, `ui_prompt_start/end`.
- Context object (ExtensionContext): `cwd`, `model`, `thinkingLevel`, `mode` (tui|rpc|json|print), `hasUI`, `ui`, `sessionManager` (getSessionId(), getSessionFile(), getCwd(), getBranch()), `modelRegistry`, `signal`, `getContextUsage()`, `compact()`, `shutdown()`, `getSystemPrompt()`, `isProjectTrusted()`. Session-control on `pi`: setModel, setActiveTools, sendUserMessage, sendMessage, appendEntry, registerTool/Command/Flag/Shortcut/Provider.
- Tools: `pi.registerTool` (TypeBox schema, execute, `exposure` direct|model-only|codemode|deferred|hidden, `annotations`); can wrap/override built-in (example tool-override.ts).

## Notes for the Proteus port
- Worker per-model ladder: spawn `pi -p --mode json --model provider/id[:level] --session-id X` (or RPC/SDK) per worktree with cwd = worktree; a lead extension can enforce the ladder by `tool_call` blocking on the spawn tool and by reading `ctx.model` in it (cap check). Models are not tied to agent files natively; the example subagent supports frontmatter `model:`.
- Enforcement hooks must be TS in-process; rewrite shell-hook logic. Blocking reason -> returned to the model as tool error (reason field).
- Extensions cannot be forced on children unless passed with `-e` (or via project .pi/extensions after trust; `-a/--approve` trusts project files for one command).
- Child pi: env `AI_AGENT=pi` set in CLI/RPC child processes.
- Volatility: 0.x, breaking changes; pin version. New-contributor PRs auto-closed (irrelevant to use).
- Security (per user's global CLAUDE.md spirit): extensions run in-process with full perms; packages via npm/git are a trust decision.
